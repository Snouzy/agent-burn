Use `--json` on either public command:

```bash
agent-burn summary --json
agent-burn summary --value --json
agent-burn summary --value --cursor-plan ultra --json
agent-burn harness claude --json
agent-burn harness codex --json
agent-burn harness kimi --json
```

Use `--jq` to filter JSON directly:

```bash
agent-burn summary --json --jq '.totals'
agent-burn summary --json --jq '.projects[:5]'
agent-burn harness claude --json --jq '.window'
agent-burn harness codex --json --jq '.spendMix'
```

Harness JSON includes `spendMix`, a trailing-30-day breakdown of input, output, cache write, and cached input token classes with token percentages and API-equivalent cost percentages. Codex harness JSON also includes `resetCreditsAvailable` when the live ChatGPT usage meter reports banked rate-limit resets, and `limitUsageDaily`: the ChatGPT Codex dashboard's last 30 days of weekly-limit consumption (`date`, `usedPercent`, plus `surfaces[]` with `surface`/`usedPercent` and `models[]` with `model`/`speed`/`usedPercent`). It is empty with `--offline` or without a signed-in Codex token.

The JSON shape is intended for dashboards and scripts. Prefer command names `summary` and `harness`.

Summary JSON also includes `daily` rows (`date`, `cost`, `tokens`). Each entry in
`agents` includes its own `models`, `daily`, and `tokenBreakdown` (`input`,
`output`, `cacheWrite`, `cacheRead`). Cursor agent `daily` rows also include
`cursorModelsCost` and `cursorModelsTokens` for Composer, Auto, and other
Cursor-hosted models. These details respect the selected date range and keep
models attributed to the correct harness, including Cursor. Existing totals and
model fields are unchanged.

The [macOS app](/docs/installation#macos-app) uses these details for its General and
harness tabs. Add `--value` to include subscription plan information.

### Projects

Summary JSON includes `projects`, the cost of each project in the selected date
range. A project is a git repository, or a working folder outside any
repository:

```json
{
  "name": "agent-burn",
  "path": "/Users/me/dev/agent-burn",
  "kind": "repository",
  "totalCost": 42.5,
  "totalTokens": 61000000,
  "percentage": 31.2,
  "agents": [
    { "agent": "claude", "totalCost": 30.1, "totalTokens": 45000000 },
    { "agent": "codex", "totalCost": 12.4, "totalTokens": 16000000 }
  ]
}
```

`kind` is one of:

- `repository`: a git repository.
- `folder`: a working folder that is not in a git repository and holds no
  repositories itself. Its path is the highest such folder, so a session in
  `~/dev/notes/drafts` counts toward `~/dev/notes`.
- `scratch`: one `Scratch` entry with a `null` path for work that belongs to
  no project: the home directory, standard home folders such as `~/Documents`
  or `~/Desktop` (folders inside them can still be projects), anything in
  `~/Library` or `~/Documents/Codex`, temp folders such as `/tmp`, Claude
  desktop scratch workspaces, and folders with a git repository among their
  children or grandchildren, such as `~/dev`.
- `other`: one final `Other` entry with a `null` path for usage with no known
  location, including agents that do not record one.

Repositories and folders come first, sorted by cost. `Scratch` and `Other`
are omitted when empty. `percentage` is the share of total
cost, or of total tokens when nothing has a cost. Project costs add up to
`totals.totalCost`. The terminal summary does not show projects.

Each model request (a turn) counts toward the repository it worked in:

- Claude Code: the files its tool calls read or edit (`file_path`, `path`,
  `notebook_path`) and the folders its shell commands `cd` into.
- Codex: the `workdir` of its tool calls and the files its `apply_patch` calls
  change.
- Kimi Code: the workspace root from `workspaces.json`.

When a turn touches several repositories, the most referenced one wins. A turn
that touches nothing counts toward the repository the session touched last, and
turns before the first touch count toward the first repository the session
touches. A Claude Code or Codex session that never touches a repository counts
toward the project of its working directory: its repository, else its folder
project, else `Scratch`. Paths outside repositories, such as `~/.claude` or `/tmp`, are
ignored.

Subfolders, git worktrees, and deleted Codex worktrees count toward the
repository they belong to, even after the folder is gone. When two projects
share a folder name, `name` includes the parent folder (`work/api`,
`perso/api`).

### Cursor account balances

Live `agent-burn summary --value --json` can include `cursorAccount` with
`billingCycleStartMs`, `billingCycleEndMs`, `includedLimitUSD`,
`includedRemainingUSD`, `includedPercentUsed`, optional `includedSpendUSD` /
`bonusSpendUSD` / `planSpendUSD`, `onDemandSpentUSD`, `onDemandLimitUSD`,
`activeRemainingUSD`, `activeLimitUSD`, `activePercentUsed`, and `grants`
(kind, total/remaining USD, expiration timestamp). Active fields follow
promotional credits while those still have remaining balance, then the included
allowance. Absent amounts are null, not zero. These current account balances
are distinct from historical API-equivalent spend and are omitted in offline
mode.

### Claude account meters

Live `agent-burn summary --value --json` can include `claudeAccount` with
`sessionUsedPercent`, `sessionResetsAtMs`, `weeklyUsedPercent`,
`weeklyResetsAtMs`, `scoped` model weeks (`name`, `usedPercent`, `resetsAtMs`),
and optional extra-usage fields (`extraEnabled`, `extraUsedUSD`,
`extraLimitUSD`, `extraUsedPercent`). Session and weekly values come from
Claude’s live OAuth usage meters, including the modern `limits` array.
Extra-usage amounts are dollars. Absent amounts are null, not zero. These
current account meters are distinct from historical API-equivalent spend and
are omitted in offline mode.

### Kimi Code account meters

Live `agent-burn summary --value --json` can include `kimiAccount` when Kimi Code
credentials are available and `--agents` includes `kimi` or is omitted. Keys:
`sessionUsedPercent` / `sessionResetsAtMs` (5-hour session),
`weeklyUsedPercent` / `weeklyResetsAtMs` (legacy plans only),
`monthlyUsedPercent` / `monthlyResetsAtMs` (monthly Kimi Code quota),
`monthlyTotalUsedPercent` / `monthlyTotalResetsAtMs` (monthly account total),
and `boosterRemaining` / `boosterTotal` / `boosterCurrency` (booster balance in
major currency units). Percents are 0–100 and reset times are epoch
milliseconds. Meters Kimi does not report are omitted, not null. These meters
are omitted in offline mode and while the stored Kimi Code access token is
expired, because Agent Burn never refreshes it.

`harness kimi --json` has no plan, price, or value multiple. Its `window` is the
weekly limit when Kimi reports one, otherwise the monthly Kimi Code quota.
